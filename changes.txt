# J~Net AI Assistant — Changes

## 2026-09-06 — v1.0.10 (update)

### Changed
- **Default OpenCode model is now `deepseek-v4-flash`** — the pre-filled OpenCode profile uses it (was `opencode-go`). Existing OpenCode profiles still on the old prefill (`opencode-go` or blank model) are migrated in place to `deepseek-v4-flash`.
- **Streaming is OFF by default** for the pre-filled OpenCode profile. Streaming can still be toggled on per profile; non-streaming replies are immune to transient mid-stream errors.
- **Chat crash hardening:** sending a chat can no longer crash the app on a transient failure — the whole request + completion handler is wrapped with try/catch that logs to the error log (E0205) and shows a friendly status instead of crashing (the occasional 1-off crash after updating is fixed; if a request fails, just send again).

### Added
- **Show API key now actually reveals the stored key:** tapping "Show" on a saved profile decrypts the encrypted API key and displays it in plaintext (not just bullets). A **copy icon** beside it copies the real key to the clipboard. Copying works even without toggling Show.
- Version bumped to 1.0.10 (versionCode 11).

## 2026-09-05 — v1.0.9 (update)

### Fixed
- **Streaming request failed / base-URL fix:** default pre-filled endpoint URLs now end with a trailing `/` (e.g. `https://opencode.ai/zen/go/v1/`, `http://localhost:11434/v1/`, `https://api.example.com/v1/`, `http://SERVER_IP:PORT/v1/`). Providers strip the trailing slash before appending their path segment, and the port stays blank when https is already in the URL — verified working with a valid API key. Existing profiles keep their current values.
- **Chat mic now transcribes (was: nothing happened on mic tap):** the mic button in the Chat bar now does speech-to-text only and places the transcribed text straight into the message box, ready to review and send. It no longer launches the full voice-assistant pipeline. The mic button glows ● while listening; tapping again cancels. (The Voice Assistant tab's mic is unchanged.)

### Added
- **Error logs entry in Settings:** a new "Error logs" row opens the diagnostics/crash-log viewer where you can Copy the log to clipboard and Clear it (plus Share).
- **History screen (Issue: history for all modes):** a dedicated History screen lists every past conversation across Normal / RAG / Hybrid / Agent / Voice modes with Open, Rename, Duplicate and Delete, plus **Export history** (writes every conversation and response to a `.txt` file) and **Clear history** (with confirmation dialog). Reached from the Chat header (history icon) and from Settings → History.
- **Voice Assistant history:** every completed voice turn (transcript + AI response) is now persisted into a Voice conversation so voice sessions appear in History too.
- **Clear history + Export history in Settings:** rows under General → "Clear history" (with confirmation) and "Export history" (SAF file picker).
- **Share conversation button:** a share icon in the Chat header copies the current conversation (chat + response) to the clipboard and opens the system share sheet.
- **Voice Assistant response actions:** the AI response now has **Copy response** (copy to clipboard), **Save clip** (synthesise the response to a WAV file in Downloads — no permission needed on Android 10+; on Android 8/9 the storage permission is requested once) and **Share** buttons.
- Version bumped to 1.0.9 (versionCode 10). v1.0.8 APK backed up to Backup/.

It is now a proper masked •••••• field that always captures input; Show/Hide only changes visibility. While editing an existing profile the app shows a "key already saved… type to replace" hint.

- **Models section added to each profile** — the editor lists models from the Models tab (active one starred); tapping one sets the profile's Model ID. At request time the profile uses its own Model ID if filled, otherwise it falls back to the active model from the Models tab.
- Profile list rows now show "key saved / no key" and "session ok" status per profile.

## 2026-09-05 — v1.0.4 (update)

### Changed
- **PIN security is never active initially.** The app auto-unlocks and opens straight away — no lock screen on a fresh install, no crash.
- **Secure mode lives entirely in Settings → Security:**
  - Toggle **ON** → enter the default PIN (`12345678`) → enter a new personal PIN → confirm it → only the PBKDF2 hash is stored → Secure mode enables.
  - Toggle **OFF** → Secure mode disables.
  - The same form doubles as "Change PIN" when Secure mode is already on.
- **Lock screen simplified to plain unlock** — the former forced-change screen (a crash source) is removed. Entering the personal PIN or `12345678` just unlocks. Reset (turn off) and copy-diagnostics remain available on the lock screen.
- Hardened startup: any initialisation failure is logged with code E0301 and the app opens unlocked instead of closing.
- v1.0.3 APK backed up to Backup/.

## 2026-09-04 — v1.0.3 (update)

### Changed
- **Secure mode is now OFF by default** and the app opens with NO PIN from a fresh install. A PIN is only required after the user enables Secure mode in Settings → Security.
- Onboarding no longer sets a PIN; its Security step explains that Secure mode defaults to OFF and shows the default PIN for later use.
- Lock screen recovery options added:
  - **Reset app protection** — type `12345678` then tap to turn Secure mode off entirely (guaranteed way back in).
  - **Copy diagnostic log** — copies the error-code log to the clipboard right from the lock screen (no unlock needed), matching how to report a crash/hang.
- **Diagnostics & crash log** in Settings → Security: view the persistent log (error codes E0001–E1001/FATAL plus timestamps and full stack traces), **Copy to clipboard**, **Share**, and **Clear**.
- Every Err log entry (with codes) is now also appended to `filesDir/jnet_diagnostics.log`; uncaught crashes and app lifecycle events are logged too (no secrets/PINs ever written).
- Unlock/change-PIN already run off the main thread (PBKDF2) and are logged step-by-step to trace hangs.
- v1.0.2 APK backed up to Backup/.

## 2026-09-04 — v1.0.2 (update)

### Fixed
- PIN unlock no longer freezes/crashes: PBKDF2 PIN verification and PIN setup now run on a background dispatcher (no main-thread hashing → no ANR), with "Unlocking…/Saving…" busy states and double-tap protection.
- `canUseBiometric()` wrapped so lock screen can't crash on devices with an unavailable biometric service.
- Unlock and Save-PIN clicks fully guarded (try/catch → inline error, never a crash).
- Added permanent crash logger: uncaught exceptions are appended to `filesDir/jnet_crash.log` with full stack traces for diagnosis.
- Default PIN flow: entering `12345678` unlocks and forces a new personal PIN.
- v1.0.1 APK backed up to Backup/.

## 2026-09-04 — v1.0.0 (initial release)

### Added
- Full Android project (Kotlin, Jetpack Compose, Material 3, MVVM, Room, WorkManager).
- 7-section bottom navigation: Chat, Documents, Models, Agents, Voice, Activity/History, Settings.
- AI connection profiles with per-profile endpoint, port, API key (encrypted), model, headers, auth type, TLS, streaming, generation params, daily/monthly token limits and connection testing.
- Providers: OpenCode, Ollama, OpenAI-compatible, custom endpoints, local-device abstraction (capability detection + graceful fallback for on-device inference).
- Streaming chat (SSE) with stop/regenerate, chat modes (Normal / RAG / Hybrid / Agent / Voice), conversation history with autotitle, rename, delete, duplicate.
- RAG: parsers for TXT/MD/PDF/CSV/XLSX/DOCX/JSON/HTML/XML/source code; chunker with overlap; embeddings via configured provider; hybrid semantic+keyword search; source citations; document collections; duplicate detection by SHA-256 hash; background indexing via WorkManager.
- Local model manager: import via file picker, metadata (size/ctx/quantisation/RAM estimate), CPU/GPU/NNA capability detection, activate/remove, low-memory warning (no crash).
- Voice: live assistant state machine (IDLE/LISTENING/TRANSCRIBING/THINKING/SPEAKING/INTERRUPTED/ERROR), Android STT + Android TTS as pluggable providers, input via mic next to the text box, voice interruption.
- Agent: extensible tool registry (calculate, open URL, clipboard, RAG search, open settings, read authorised file, time, device info), permission categories, trust levels (ask/destructive/trusted/disabled), strict argument validation, no raw shell execution, action log.
- Security: Android Keystore AES-256 encryption for API keys; app lock with PIN (PBKDF2 salted hash), biometric unlock, auto-lock timeout; encrypted backup/export with integrity checksum; never stores or logs secrets.
- Usage/token accounting (today/total, per profile daily & monthly limits, hard-stop) and an activity log with clear-history.
- First-launch onboarding with "Use local AI" skip-cloud option.
- About screen: Made by jnetai.com, full version, Check for update (GitHub latest tag, fallback to repo), Share app.
- Dark-first neon UI, persistent debug logging with stable error codes (E0001–E1001), no intrusive dialogs.
- GitHub Actions release workflow (tag push) using repo secrets KEYSTORE_BASE64/KEYSTORE_PASSWORD/KEY_ALIAS/KEY_PASSWORD for a stable in-place-updatable signing key.
- Unit tests: chunking, hybrid ranking helpers, agent arg validation, expression evaluator, profile/auth logic.

### Notes
- Release APK signed with a stable app-specific keystore. Backed up under Backup/ and password recorded in the password vault.
- Local on-device GGUF inference engine is not bundled (APK-size/memory); the interface exists and degrades gracefully with clear guidance.
- Release uses unminified (no R8) build because Apache POI/xmlbeans carry opt-in classpath references that break R8; correctness and easy crash diagnosis prioritised.
- Release URL (no tag/file to avoid direct download): https://github.com/jnetai-clawbot/jnet-ai-assistant/releases
